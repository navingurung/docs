# NTA v3 Cutover — Backend Implementation Spec

Backend only (`taimatsu-tax-free-backend`). Code shown is diffed
against the actual current files reviewed — not hypothetical.

---

## Summary

Today, `POST /refund/` (`RefundApp/routers/refund.py`) trusts the
caller to send a `form` that already matches NTA's exact field
shape (`RefundRequest` in `schemas/refund.py` — includes
`generalTotal`, `consumTotal`, `goodsType`, etc.) and forwards it to
NTA almost unchanged. This works today because only one NTA version
(V2) exists.

From Nov 1, 2026, **two shapes must be supported at once** — V2
(current) and V3 (new) — selected per record by that sale's
`sellDate`, never by "today." V2 stays valid until **2027-04-30**.
This doc lists each concrete backend change needed, with real code.

**Not addressed here (separate, later work):** what the frontend
sends instead of the current full NTA-shaped `form` — that's a
joint decision with the frontend team, not yet made. The code below
shows the backend side changes with the current `form`-based
approach kept as the input for now, so the diffs are grounded in
what actually exists; swapping the input to a leaner "raw order"
shape is a follow-up change once that contract is agreed.

**No new files needed.** Every change below adds to an existing
file (`schemas/refund.py`, `utils/refunds.py`, `routers/refund.py`,
`models.py`, and `AdminApp/routers/refund.py`) — matching this
codebase's existing structure rather than introducing new modules.

---

## Change 1 — Add a V3 schema alongside V2 (standalone, no shared base)

`schemas/refund.py` gets a new class added — **not** modifying
`RefundRequest` (V2) at all, so V2 stays exactly as-is until its
2027-04-30 removal date.

```python
# schemas/refund.py — ADD (existing RefundRequest/DetailItem untouched)

from pydantic import model_validator


class DetailItemV3(SQLModel):
    serial: int
    goodsName: str
    number: int
    price: int  # tax-excluded, per unit
    reduced: int
    goodsType: Optional[int] = None      # new meaning in v3 — optional,
                                          # broader product-category code,
                                          # NOT the old general/consumables split
    goodsInfo: Optional[str] = None      # required if price >= 1,000,000
    serialNumber: Optional[str] = None   # required if price >= 1,000,000

    @model_validator(mode="after")
    def check_high_value_item(self):
        if self.price >= 1_000_000 and not (self.goodsInfo or self.serialNumber):
            raise ValueError(
                "goodsInfo or serialNumber is required for items priced "
                "\u00a51,000,000 or more (tax-excluded)"
            )
        return self


class RefundRequestV3(SQLModel):
    senderId: str
    senderIdType: int
    sendNo: str
    proceduresId: str
    version: int = 3
    name: str
    nation: str
    birth: str
    status: str
    landDate: str
    docType: str
    passportNo: str
    shopId: str
    shopType: int
    shopName: str
    shopPlace: str
    bizName: str
    bizPlace: str
    sellDate: str
    transOrNot: str
    # generalTotal / consumTotal removed — no general/consumables split in v3
    lqExemptOrNot: str
    details: List[DetailItemV3]
    note: Optional[str] = None


class RefundCreateRequestV3(SQLModel):
    model_config = ConfigDict(populate_by_name=True)

    form: RefundRequestV3
    metadata_: RefundMetadata = Field(alias="metadata")  # unchanged, reused as-is
```

## Change 2 — Version resolver (single source of truth)

Added into the **existing** `RefundApp/utils/refunds.py` — it's
already this codebase's shared-helpers file (refund status buckets,
amount calc, etc.), so this fits the existing convention instead of
introducing a new `services/` folder that doesn't exist anywhere
else in the repo.

```python
# utils/refunds.py — ADD (existing REFUND_* constants and functions untouched)

from datetime import date, datetime

CUTOVER_DATE = date(2026, 11, 1)
V2_REMOVAL_DATE = date(2027, 4, 30)  # mark V2 code for deletion after this


def resolve_nta_version(sell_date_str: str) -> int:
    """
    sell_date_str is RefundRequest.sellDate / RefundRequestV3.sellDate,
    format YYYYMMDD (matches the real payload sample: "20260825").
    Keyed on the SALE date, never "today" or submission time — a
    pre-cutover sale stays V2 for its entire lifecycle, including any
    later cancellation. Never converts a V2 sale to V3.
    """
    sell_date = datetime.strptime(sell_date_str, "%Y%m%d").date()
    return 2 if sell_date < CUTOVER_DATE else 3


def resolve_nta_url(base_url: str, sell_date_str: str) -> str:
    version = resolve_nta_version(sell_date_str)
    return f"{base_url}/v{version}/purchaseRecord/reception"
```

**⚠️ Note:** `NTA_TEST_URL` today is a flat URL (no version segment
baked in per the `.env.sample`) — confirm with the team whether the
env var should change to a base URL only (`https://api.menzei-test.nta.go.jp`)
with the version path appended by `resolve_nta_url`, since the
current single flat URL can't represent two versions at once.

## Change 3 — `create_refund` accepts either shape, routes by version

Current code (`routers/refund.py`, lines 115–141) only ever builds
one `RefundRequest`. Diff below shows the minimal change to accept
either shape and route correctly — actual field-by-field validation
already lives in each schema (Change 1), so this function stays
thin.

```python
# routers/refund.py — BEFORE (current, relevant excerpt)

@router.post("/")

    request: RefundCreateRequest,      # <- only ever V2 shape
    session: SessionDep,
    current_shop: CurrentShop,
):
    form = request.form
    ...
    url = f"{NTA_URL}"                 # <- flat, single URL
    body = form.model_dump()
    resp = send_post_request(url=url, headers=headers, payload=body)
```

```python
# routers/refund.py — AFTER

from RefundApp.utils.refunds import resolve_nta_version, resolve_nta_url
from RefundApp.schemas.refund import RefundCreateRequest, RefundCreateRequestV3

NTA_BASE_URL = require_env("NTA_TEST_URL")  # now a base URL, no version segment


@router.post("/")
async def create_refund(
    request: RefundCreateRequest | RefundCreateRequestV3,  # accept either
    session: SessionDep,
    current_shop: CurrentShop,
):
    form = request.form
    metadata = request.metadata_
    ...
    version = resolve_nta_version(form.sellDate)

    # Defensive check — the shape sent must match what sellDate implies.
    # Catches a stale client sending a v2 payload for a v3-era sale (or
    # vice versa) before it ever reaches NTA.
    is_v3_shape = isinstance(request, RefundCreateRequestV3)
    if (version == 3) != is_v3_shape:
        raise HTTPException(
            status_code=422,
            detail=(
                f"sellDate {form.sellDate} requires v{version} shape, "
                f"but request was v{3 if is_v3_shape else 2}"
            ),
        )

    url = resolve_nta_url(NTA_BASE_URL, form.sellDate)
    body = form.model_dump()
    resp = send_post_request(url=url, headers=headers, payload=body)
    ...
```

**This defensive check is also the natural home for "stale-client
detection"** (task from the earlier doc) — a 422 here already tells
an outdated POS terminal something is wrong; whether to also add a
softer warning path (vs. hard rejection) is worth deciding with
Fuga, but the check itself is cheap to add now.

## Change 4 — Store which version was used, explicitly

Today, `version` only exists inside the encrypted `request_body`
blob (`RefundRecord.request_body`) — not queryable without
decrypting every row. Worth adding as its own column for audits and
for `AdminApp` to trust without decryption.

```python
# models.py — RefundRecord, ADD one field

class RefundRecord(SQLModel, table=True):
    ...
    nta_version: int = Field(nullable=False, default=2)  # NEW
```

```python
# routers/refund.py — where RefundRecord is created (line ~211), ADD

refund_rec = RefundRecord(
    send_no=body["sendNo"],
    request_body=encrypt(body),
    response_body=encrypt(resp.json()),
    nta_version=version,          # NEW — from Change 3's resolve_nta_version
    shop_id=shop_id,
    order_id=orderId,
    delete_request_body=None,
    delete_response_body=None,
)
```

**Needs an Alembic migration** (`alembic revision --autogenerate`)
in this repo, **and** the same field manually added to
`AdminApp/models.py`'s own `RefundRecord` definition — the two
repos keep separate model classes against the same shared table.

## Change 5 — `AdminApp` cancellation stays version-safe

Current `AdminApp/routers/refund.py` cancellation flow already
reuses the stored `request_body` and just negates amounts — this
naturally preserves whichever version the original submission used,
**no code change strictly required**. Change 4's new `nta_version`
column makes this explicit and checkable instead of implicit:

```python
# AdminApp/routers/refund.py — ADD as a safety assertion before resend

if refund_record.nta_version == 3:
    url = f"{NTA_BASE_URL}/v3/purchaseRecord/reception"
else:
    url = f"{NTA_BASE_URL}/v2/purchaseRecord/reception"
# (replaces today's flat `url = f"{NTA_URL}"` on the cancellation path too)
```
